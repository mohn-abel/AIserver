# 项目关键模块调用流程

本文以当前工作区源码为准，按关键子系统整理主要调用顺序。每个节点给出实际函数或类名，并说明该步骤的职责；Muduo、OpenSSL、libcurl、RabbitMQ 和 MySQL 等外部组件只保留与项目交互的边界。

## 一、服务启动与 HTTP 框架

### 1. 服务启动与应用初始化

主要源码：

- `AIApps/ChatServer/src/main.cpp`
- `AIApps/ChatServer/src/ChatServer.cpp`
- `HttpServer/src/http/HttpServer.cpp`

```text
进程进入 main(argc, argv)
-> getopt() 解析 -p 参数，确定监听端口，默认端口为 80
-> ChatServer::ChatServer(port, serverName)
   -> HttpServer::HttpServer(port, name, useSSL=false, option)
      -> HttpServer::initialize()
         -> Muduo TcpServer::setConnectionCallback() 注册 HttpServer::onConnection()
         -> Muduo TcpServer::setMessageCallback() 注册 HttpServer::onMessage()
   -> ChatServer::initialize()
      -> MysqlUtil::init() 初始化全局 DbConnectionPool，预建数据库连接
      -> ThreadPool::ThreadPool(8) 创建 AI 业务线程池
      -> ChatServer::initializeSession()
         -> 创建 MemorySessionStorage
         -> 创建 SessionManager
         -> HttpServer::setSessionManager() 注入会话管理器
      -> ChatServer::initializeMiddleware()
         -> 创建 CorsMiddleware
         -> HttpServer::addMiddleware() 加入中间件链
      -> ChatServer::initializeRouter()
         -> HttpServer::Get()/Post() 注册页面、认证、聊天和会话 Handler
         -> Router::registerHandler() 保存“HTTP 方法 + 路径 -> Handler”映射
-> ChatServer::setThreadNum(4) 配置 Muduo I/O 线程数量
-> StrategyFactory::loadFromConfig(model_config.json) 加载并注册模型策略
-> GatewayConfig::loadFromFile(gateway_config.json) 加载网关治理配置
   -> 加载成功：LLMGateway::init() 初始化限流、熔断和 fallback 路由
   -> 加载失败：网关保持未初始化，后续 LLM 请求采用直通模式
-> ChatServer::initChatMessage()
   -> ChatServer::readDataFromMySQL() 读取历史消息
   -> 为每个 userId/sessionId 创建或复用 AIHelper
   -> AIHelper::restoreMessage() 按数据库顺序恢复内存上下文
-> RabbitMQThreadPool::start() 启动 SQL 队列消费线程
-> ChatServer::start()
   -> HttpServer::start()
      -> Muduo TcpServer::start() 开始监听
      -> EventLoop::loop() 进入网络事件循环
```

### 2. HTTP 请求接入、解析、路由与响应

主要源码：

- `HttpServer/src/http/HttpServer.cpp`
- `HttpServer/src/http/HttpContext.cpp`
- `HttpServer/src/http/HttpResponse.cpp`
- `HttpServer/src/router/Router.cpp`

```text
客户端建立 TCP 连接
-> Muduo 触发 HttpServer::onConnection(conn)
-> conn->setContext(HttpContext()) 为连接创建 HTTP 解析状态
-> 客户端发送数据
-> Muduo 触发 HttpServer::onMessage(conn, buf, receiveTime)
-> HttpContext::parseRequest(buf, receiveTime) 运行 HTTP 状态机
   -> HttpContext::processRequestLine() 解析方法、路径、查询参数和 HTTP 版本
   -> HttpRequest::addHeader() 收集请求头
   -> POST/PUT 请求读取 Content-Length 指定的请求体
   -> 数据不足：保留解析状态，等待下一批网络数据
   -> 格式错误：发送 400 Bad Request，并关闭连接
-> HttpContext::gotAll() 判断请求是否完整
-> HttpServer::onRequest(conn, request)
   -> 根据 Connection 头和 HTTP 版本决定长连接或短连接
   -> 创建 HttpResponse，并通过 HttpResponse::setConnection() 保存当前连接
   -> HttpServer::handleRequest(request, response)
      -> MiddlewareChain::processBefore() 顺序执行请求前置中间件
      -> Router::route() 查找并执行 Handler 或回调
      -> 未找到路由：设置 404 Not Found
      -> MiddlewareChain::processAfter() 逆序执行响应后置中间件
      -> 业务异常：设置 500 响应
-> 如果 HttpResponse::isDeferred() == true
   -> 当前 I/O 调用栈不发送普通响应
   -> 后续由业务线程通过 runInLoop() 回到 I/O 线程发送 JSON/SSE
-> 否则
   -> HttpResponse::appendToBuffer() 组装状态行、响应头和响应体
   -> TcpConnection::send() 发送响应
   -> HttpResponse::closeConnection() == true 时调用 shutdown()
-> HttpContext::reset() 清空本次请求，准备解析同一连接上的下一次请求
```

### 3. Router 路由注册与匹配

主要源码：

- `HttpServer/include/http/HttpServer.h`
- `HttpServer/src/router/Router.cpp`

```text
ChatServer::initializeRouter()
-> HttpServer::Get()/Post()
-> Router::registerHandler(method, path, handler)
-> 以 RouteKey{method, path} 保存静态 Handler

请求进入 Router::route(req, resp)
-> 先按“请求方法 + 完整路径”查找静态 Handler
   -> 命中：RouterHandler::handle(req, resp)
-> 否则查找静态函数回调
   -> 命中：HandlerCallback(req, resp)
-> 否则遍历 regexHandlers_
   -> 方法和正则均匹配：extractPathParameters() 写入路径参数
   -> RouterHandler::handle(newReq, resp)
-> 否则遍历 regexCallbacks_
   -> 方法和正则均匹配：执行动态路由回调
-> 全部未命中：返回 false，由 HttpServer::handleRequest() 生成 404
```

### 4. Middleware 中间件链与 CORS

主要源码：

- `HttpServer/src/middleware/MiddlewareChain.cpp`
- `HttpServer/src/middleware/cors/CorsMiddleware.cpp`

```text
HttpServer::handleRequest()
-> MiddlewareChain::processBefore(request)
-> 按注册顺序调用每个 Middleware::before()
-> CorsMiddleware::before(request)
   -> 非 OPTIONS：继续进入路由
   -> OPTIONS 预检请求：CorsMiddleware::handlePreflightRequest()
      -> CorsMiddleware::isOriginAllowed() 检查 Origin
      -> 不允许：设置 403
      -> 允许：CorsMiddleware::addCorsHeaders() 添加跨域头并设置 204
      -> 抛出已构造的 HttpResponse，中断后续路由
-> 普通请求完成 Router::route()
-> MiddlewareChain::processAfter(response)
-> 按注册逆序调用 Middleware::after()
-> CorsMiddleware::after(response)
   -> CorsMiddleware::addCorsHeaders() 为正常业务响应补充跨域响应头
```

### 5. Session 获取、创建、续期与销毁

主要源码：

- `HttpServer/src/session/SessionManager.cpp`
- `HttpServer/src/session/SessionStorage.cpp`
- `HttpServer/src/session/Session.cpp`

```text
Handler 调用 SessionManager::getSession(req, resp)
-> SessionManager::getSessionIdFromCookie() 从 Cookie 提取 sessionId
-> 如果存在 sessionId
   -> MemorySessionStorage::load(sessionId)
   -> 会话存在且未过期：返回原 Session
   -> 会话已过期：从内存存储删除并返回空
-> 如果会话不存在、Cookie 无效或会话已过期
   -> SessionManager::generateSessionId() 生成 32 位十六进制 ID
   -> 创建 Session(sessionId, manager)
   -> SessionManager::setSessionCookie() 在响应中加入 Set-Cookie
-> Session::refresh() 延长过期时间
-> MemorySessionStorage::save() 保存或更新会话
-> Handler 通过 Session::getValue()/setValue() 读取或写入登录状态

登出时
-> Session::clear() 清空会话数据
-> SessionManager::destroySession(sessionId)
-> MemorySessionStorage::remove(sessionId) 删除会话
```

### 6. SSL/HTTPS 接入流程

主要源码：

- `HttpServer/src/http/HttpServer.cpp`
- `HttpServer/src/ssl/SslContext.cpp`
- `HttpServer/src/ssl/SslConnection.cpp`

```text
应用启用 SSL 并调用 HttpServer::setSslConfig(config)
-> SslContext::initialize()
   -> OpenSSL 初始化并创建服务端 SSL_CTX
   -> SslContext::loadCertificates() 加载证书、私钥并校验匹配关系
   -> SslContext::setupProtocol() 设置协议与加密套件
   -> SslContext::setupSessionCache() 配置 TLS 会话缓存

客户端建立 HTTPS 连接
-> HttpServer::onConnection(conn)
-> 创建 SslConnection(conn, sslCtx)
-> SslConnection::startHandshake()
-> SslConnection::handleHandshake()
   -> 握手需更多数据：等待下一次 onRead()
   -> 握手成功：状态切换为 ESTABLISHED
   -> 握手失败：关闭 TCP 连接
-> SslConnection::onRead() 接收加密数据
   -> 握手阶段：写入 BIO 后继续 handleHandshake()
   -> 已建立阶段：SSL_read() 解密数据
   -> 调用上层 messageCallback_，把解密内容交回 HTTP 处理
```

当前源码接线说明：

```text
SslConnection::send() 已实现“SSL_write() -> 从 write BIO 取出密文 -> TcpConnection::send()”
-> 但 HttpServer::onRequest() 的普通响应和 SSE 辅助函数当前直接调用 TcpConnection::send()
-> 当前 HTTP 响应主链没有调用 SslConnection::send()

解密回调进入 HttpServer::onMessage()
-> HttpServer::onMessage() 在 useSSL_ 为 true 时又调用 SslConnection::onRead()
-> 因此当前接线会再次经过 SSL 分支；文档不把它描述成已完成的纯明文 HTTP 交接
```

### 7. ThreadPool 业务线程池

主要源码：

- `HttpServer/include/utils/ThreadPool.h`
- `HttpServer/src/utils/ThreadPool.cpp`

```text
ThreadPool::ThreadPool(numThreads)
-> 创建 numThreads 个 worker
-> 每个 worker 等待 condition_variable

调用方执行 ThreadPool::enqueue(task)
-> 把 task 包装成 packaged_task
-> 获取 future
-> 加锁后把任务加入 tasks_ 队列
-> notify_one() 唤醒一个 worker
-> worker 从队首取出任务并执行
-> packaged_task 写入结果或异常，调用方可通过 future 获取

ThreadPool::~ThreadPool()
-> 设置 stop_ = true
-> notify_all() 唤醒全部 worker
-> worker 完成队列中剩余任务后退出
-> join() 等待所有 worker 结束
```

### 8. MySQL 连接池与查询封装

主要源码：

- `HttpServer/include/utils/MysqlUtil.h`
- `HttpServer/src/utils/db/DbConnection.cpp`
- `HttpServer/src/utils/db/DbConnectionPool.cpp`

```text
ChatServer::initialize()
-> MysqlUtil::init(host, user, password, database, poolSize)
-> DbConnectionPool::getInstance().init()
-> DbConnectionPool::createConnection() 预建连接并放入 deque

业务调用 MysqlUtil::executeQuery()/executeUpdate()
-> DbConnectionPool::getConnection()
   -> 连接池为空：等待 cv_，超过 acquireTimeout_ 抛出 DbException
   -> 从 deque 尾部取最近归还的热连接
   -> DbConnection::ping() 检查连接
      -> ping 成功：继续使用
      -> ping 失败：DbConnection::reconnect()
      -> 重连仍失败：DbConnectionPool::spawnReplacement() 新建替代连接
-> DbConnection::executeQuery()/executeUpdate()
   -> 创建 PreparedStatement
   -> bindParams() 绑定参数
   -> 执行 SQL
-> 查询场景由 QueryResult 同时持有连接、Statement 和 ResultSet
-> 查询结果或更新函数结束后，智能指针触发 PoolDeleter::operator()(conn)
-> DbConnectionPool::returnConnection() 把连接放回 deque 尾部并唤醒等待线程
```

后台健康检查：

```text
DbConnectionPool 构造时启动 checkConnections() 后台线程
-> 每轮从 deque 头部扫描冷连接，跳过刚归还或刚检查的连接
-> 在锁内暂时摘出待检查连接
-> 在锁外调用 DbConnection::ping()，避免阻塞业务取连接
-> ping 失败时尝试 reconnect()，仍失败则 spawnReplacement()
-> 把检查后的连接按原位置放回，并通知等待线程
```

### 13. 已有会话 SSE 聊天

主要源码：

- `AIApps/ChatServer/src/handlers/ChatSendHandler.cpp`
- `AIApps/ChatServer/src/AIUtil/AIHelper.cpp`

```text
POST /chat/send
-> ChatSendHandler::handle(req, resp)
-> SessionManager::getSession() 并检查 isLoggedIn
   -> 未登录：返回 401 普通 JSON 响应
-> json::parse() 读取 question、sessionId、modelType、enableTools
   -> modelType 缺省：使用 StrategyFactory::getDefaultModel()
   -> enableTools 缺省：true
-> HttpResponse::setDeferred() 禁止当前 I/O 栈发送普通响应
-> ThreadPool::enqueue() 把阻塞式 LLM 工作投递到业务线程池
-> 业务线程加锁访问 ChatServer::chatInformation[userId][sessionId]
   -> 会话不存在：创建 AIHelper
   -> 会话存在：复用 AIHelper 及其历史 messages
-> HttpResponse::sendSSEHeaders(conn) 发送 chunked SSE 响应头
-> AIHelper::chat(..., onChunk) 执行模型对话
-> 每次 onChunk(content)
   -> Handler 包装成 OpenAI 风格 chat.completion.chunk JSON
   -> EventLoop::runInLoop() 切回连接所属 I/O 线程
   -> HttpResponse::sendSSEChunk() 发送 data 事件
-> AIHelper::chat() 正常结束
   -> EventLoop::runInLoop()
   -> HttpResponse::sendSSEEnd() 发送 [DONE] 和 chunked 结束帧
-> 业务或流式回调异常
   -> EventLoop::runInLoop()
   -> HttpResponse::sendSSEError() 发送错误事件并结束流
```

### 15. AIHelper 直接流式对话与上下文裁剪

主要源码：`AIApps/ChatServer/src/AIUtil/AIHelper.cpp`

```text
AIHelper::chat(userId, userName, sessionId, question, modelType, enableTools, onChunk)
-> 加锁保护当前会话的 strategy 和 messages
-> AIHelper::prepareStrategy(modelType) 切换本次请求使用的模型策略
-> 如果 enableTools == false 或 strategy->supportTools() == false
   -> AIHelper::addMessage() 把原始用户问题加入 messages，并投递持久化
   -> AIHelper::completeStreaming()
      -> AIHelper::buildRequestWithContext() 构造模型请求
         -> 未超过 maxContext：保留全部 messages

      -> AIStrategy::parseStreamChunk() 从每个 data JSON 提取文本
      -> 累加 fullResult，并调用 Handler 提供的 onChunk
   -> AIHelper::addMessage() 把完整 AI 回答加入 messages，并投递持久化
```

### 16. 工具路由、执行与最终回答

主要源码：

- `AIApps/ChatServer/src/AIUtil/AIHelper.cpp`
- `AIApps/ChatServer/src/AIUtil/AIConfig.cpp`
- `AIApps/ChatServer/src/AIUtil/AIToolRegistry.cpp`

```text
AIHelper::chat() 收到 enableTools=true，且当前 AIStrategy::supportTools() == true
-> AIConfig::loadFromFile(config.json) 加载 prompt_template 和工具列表
   -> 加载失败：退化为 AIHelper::completeStreaming() 直接回答
-> AIHelper::routeToolCall()
   -> AIConfig::buildPrompt(userQuestion)
      -> AIConfig::buildToolList() 生成工具名称、参数和描述
      -> 替换 {user_input} 与 {tool_list}，形成工具路由 prompt
   -> 临时把 routePrompt 放入 messages
   -> AIHelper::buildRequestWithContext() 构造第一次请求
   -> AIHelper::executeCurl()
      -> LLMGateway::call() 发起第一次非流式 LLM 调用
   -> AIStrategy::parseResponse() 提取模型返回文本
   -> AIConfig::parseAIResponse() 解析工具决策 JSON
      -> 新格式：{"need_tool":true,"tool":"get_time","args":{}}
      -> 兼容旧格式：{"tool":"get_weather","args":{...}}
      -> 非 JSON 或 need_tool=false：视为不调用工具
   -> 移除临时 routePrompt
-> 如果需要工具
   -> 创建 AIToolRegistry
      -> 构造函数通过 registerTool() 注册 get_weather 和 get_time
   -> AIToolRegistry::invoke(toolName, args)
      -> 找不到工具：抛异常并向前端输出工具调用失败
      -> 找到工具：执行对应 ToolFunc，得到 JSON 结果
   -> AIConfig::buildToolResultPrompt() 拼接原问题、工具参数和工具结果
-> 如果不需要工具
   -> 直接把原始 userQuestion 作为 finalPrompt
-> 临时把 finalPrompt 放入 messages
-> AIHelper::completeStreaming() 发起第二次流式 LLM 调用
-> 前端只收到第二次调用产生的最终 SSE 文本
-> 移除临时 finalPrompt
-> AIHelper::addMessage() 仅保存原始用户问题和完整最终回答
```

工具路由失败分支：

```text
AIHelper::routeToolCall() 或 LLMGateway::call() 抛异常
-> AIHelper::chat() 生成“路由调用失败”文本
-> 保存原始问题和错误回答
-> onChunk(error) 把错误作为 SSE 内容返回
-> 不再执行工具和第二次 LLM 调用
```

### 18. 两级令牌桶限流

主要源码：`AIApps/ChatServer/src/LLMGateway/RateLimiter.cpp`

```text
一次网关业务请求进入
-> RateLimiter::checkUserAllowed(userId)
   -> userId <= 0 或用户限流关闭：直接放行
   -> 首次出现的 userId：创建 TokenBucket
   -> TokenBucket::tryConsume()
      -> TokenBucket::refill() 按距离上次请求的时间补充令牌
      -> 有令牌：消费 1 个并放行
      -> 无令牌：抛 RateLimitException
-> 每次准备尝试一个实际后端
   -> RateLimiter::checkBackendAllowed(backendId)
   -> 后端未显式配置桶：直接放行
   -> 已配置：TokenBucket::tryConsume()
   -> 无令牌：非流式流程跳过该后端；流式流程直接抛异常

一次非流式业务请求只消费一次用户令牌
-> 主后端和每个 fallback 分别消费自己的后端令牌
```

### 19. 非流式调用与 fallback

主要源码：`AIApps/ChatServer/src/LLMGateway/LLMGateway.cpp`

```text
AIHelper::executeCurl()
-> LLMGateway::call(modelId, payload, primaryUrl, primaryKey, userId)
-> 如果网关未初始化或 config.enabled == false
   -> LLMGateway::executeHttp(primaryUrl, primaryKey, payload.dump())
   -> json::parse() 解析完整响应
   -> 不执行限流、熔断或 fallback
-> 网关启用
   -> RateLimiter::checkUserAllowed(userId)
   -> 构造主 BackendConfig
   -> LLMGateway::tryBackend(primary, payload, userId, result)
      -> RateLimiter::checkBackendAllowed(primary.id)
      -> 为 fallback 实际模型按需替换 payload["model"]；主后端保持策略构造的请求体
      -> CircuitBreaker::allowRequest() 申请 permit
         -> 不放行：该后端本次失败，返回 false
      -> LLMGateway::executeHttp() 执行 libcurl POST
         -> 设置连接超时和总请求超时
         -> 收集完整响应体并读取 HTTP 状态码
         -> curl 超时：抛 TimeoutException
         -> 其他传输错误：抛 BackendException
         -> HTTP >= 400：按状态码语义抛 BackendHttpException
      -> HTTP 2xx：保存响应体、后端 ID、permit 和耗时
   -> 主后端返回合法 JSON
      -> CircuitBreaker::reportSuccess(permit)
      -> 返回 JSON
   -> 主后端响应体不是合法 JSON
      -> CircuitBreaker::reportFailure(permit)
      -> 进入 fallback 链
   -> 遍历 GatewayConfig::routing[modelId]
      -> 找不到后端配置：跳过该 fallback
      -> 对 fallback 再次调用 tryBackend()
      -> 成功且 JSON 合法：上报成功并返回
      -> 失败或 JSON 非法：继续下一个 fallback
   -> 所有后端耗尽：抛 BackendException，由上层转成业务/SSE 错误
```

HTTP 错误的治理语义：

```text
classifyBackendHttpStatus(httpCode)（LLMGateway.cpp 内部辅助函数）
-> 400/404/422 等客户端请求错误：不计熔断失败，不尝试 fallback
-> 401/403 鉴权错误：不计熔断失败，不尝试 fallback
-> 429 后端限流：计入熔断失败，允许尝试 fallback
-> 408/5xx 后端不可用：计入熔断失败，允许尝试 fallback
-> 网络、超时等 GatewayException：计入熔断失败，允许尝试 fallback
```

### 20. 流式调用与 SSE 转发

主要源码：`AIApps/ChatServer/src/LLMGateway/LLMGateway.cpp`

```text
AIHelper::completeStreaming()
-> LLMGateway::callStreaming(modelId, payload, primaryUrl, primaryKey, userId, onChunk)
-> 网关未初始化或禁用
   -> LLMGateway::executeHttpStreaming() 直连主后端
-> 网关启用
   -> RateLimiter::checkUserAllowed(userId)
   -> RateLimiter::checkBackendAllowed(modelId)
   -> payload.dump() 在申请熔断 permit 前完成序列化
   -> CircuitBreaker::allowRequest()
      -> 不放行：抛 CircuitOpenException
   -> LLMGateway::executeHttpStreaming()
      -> 设置超时、认证头、JSON 头和策略额外请求头
      -> libcurl 每收到一批字节调用 streamingWriteCallback()
      -> StreamContext 缓存跨批次的半行数据
      -> 按换行拆分 SSE，只处理 data: 行
      -> 忽略后端 [DONE]
      -> 每个其他 data 内容交给 AIHelper 的 onChunk
      -> HTTP >= 400：抛按语义分类的 BackendHttpException
      -> HTTP 2xx 但没有 data 行：抛 BackendException，避免空白回答
   -> 完整流正常结束：CircuitBreaker::reportSuccess(permit)
   -> 可用性错误：CircuitBreaker::reportFailure(permit) 后继续向上抛出
   -> 客户端或鉴权错误：释放 permit，但不计熔断失败
-> 异常最终由 ChatSendHandler/ChatCreateAndSendHandler 转成 SSE error

流式调用不进入 fallback
-> 原因：部分 token 可能已经发送给前端，切换后端无法回滚已发送内容
```

### 21. 熔断器状态机

主要源码：`AIApps/ChatServer/src/LLMGateway/CircuitBreaker.cpp`

```text
请求前调用 CircuitBreaker::allowRequest()
-> CLOSED：直接返回当前 generation permit
-> OPEN 且未到 recoveryTimeout：拒绝请求
-> OPEN 且已到恢复时间：切换 HALF_OPEN，重置本轮探测计数
-> HALF_OPEN 未达到 halfOpenMaxCalls：返回 permit
-> HALF_OPEN 已达到探测上限：拒绝请求

并发安全：
-> 上述状态检查、冷却判断、状态转换和探测计数均由 CircuitBreaker::mutex_ 串行保护
-> 多线程不会重复进入 HALF_OPEN，也不会突破 halfOpenMaxCalls

请求成功调用 CircuitBreaker::reportSuccess(permit)
-> permit 不属于当前 generation：忽略过期结果
-> CLOSED：只有最后一次失败已超过 failureResetTimeout 时才清零失败计数
-> HALF_OPEN：累计成功探测
   -> 达到 successThreshold 且当前已完成探测均成功：切换 CLOSED

请求失败调用 CircuitBreaker::reportFailure(permit)
-> permit 过期：忽略
-> HALF_OPEN：任一探测失败，立即重新 OPEN
-> CLOSED：必要时先按失败衰减时间重置旧计数
-> 连续失败数加 1
-> 达到 failureThreshold：切换 OPEN 并记录打开时间

代际保护：
-> CLOSED 打开、OPEN 进入 HALF_OPEN、半开失败重新 OPEN 或恢复 CLOSED 时递增 generation
-> 旧 generation 的迟到成功/失败上报被忽略，不能污染新一轮状态
```

### 22. 聊天消息异步写入 RabbitMQ 和 MySQL

主要源码：

- `AIApps/ChatServer/src/AIUtil/AIHelper.cpp`
