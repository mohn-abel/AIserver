# GDB 学习笔记重组设计

## 目标

将 `调试学习.md` 重组为一份面向本项目日常调试的操作指南。读者应能从准备环境开始，按请求追踪、崩溃、卡死三类场景完成一次调试。

## 内容结构

1. 调试前准备：Debug 构建验证、依赖安装和启动命令。
2. 一次 HTTP 请求的跟踪：设置断点、触发请求、单步和变量查看。
3. 崩溃与 Core Dump：现场定位和事后分析。
4. 卡死与多线程：附加进程、线程栈快照和阻塞点判断。
5. 精准观察工具：条件断点、watchpoint 和断点命令脚本。
6. 常用命令速查与项目断点锚点。

## 示例约定

所有构建和启动示例使用项目已验证的 Debug 产物：

```bash
./build-debug/http_server -p 8080
```

环境验证使用 `build-debug/CMakeCache.txt`。源码断点使用函数名，避免依赖易变的行号。Core Dump 的可执行文件路径也使用 `./build-debug/http_server`。

## 范围与验证

仅修改 `调试学习.md`，不改变程序代码、构建配置或现有项目流程文档。完成后检查文档内不再引用 `build/http_server` 或 `build/CMakeCache.txt`，并核对命令与 README 的 Debug 构建约定一致。
